# How these results connect to the `notebooks` project

The two projects study the same phenomenon — loss of plasticity in networks trained on long task sequences — with different tools. This project (`toy_models_for_lop`, package `plasticity`) works on tiny toy networks and on factor-structured image datasets (Shapes3D, MPI3D, CIFAR-10), and has moved to acquisition assays against fresh networks. The `notebooks` project (package `tasksim`) works on MNIST with CNNs and MLPs: it stress-tests task-distance metrics, measures curvature along streams, and dissects ReLU unit death in very long (800–8,000-task) full-batch streams.

Its summaries: [`../../notebooks/results_summaries/README.md`](../../notebooks/results_summaries/README.md). Its data: `$HPCVAULT/notebooks_results` (= `~/notebooks/results`) and `$WORK/tasksim_results`.

## Where the results agree

| **Fixed inputs + changing labels → absorbing unit death** | fixed-pool absorption lemma and the 4-unit toy ([01 E1](01_toy_models_and_theory.md)); Shapes3D feature-switch stream kills its first layer ([02 E1](02_shapes3d_streams.md)); unfreezing the factor-rule encoder kills units with exactly zero gradient ([03](03_factor_rule_stream.md)) | `permuted_classes` / `random_labels_20` (fixed images): 0 of 1,615 hidden-1 deaths revive; deaths are 100% optimizer-driven ([05 E2–E3](../../notebooks/results_summaries/05_unit_death.md)) |
| **Input drift keeps the first layer alive; damage accumulates in the second** | Shapes3D permuted-pixel stream: first layer 22–30 of 30 alive, second falls to 4–8 ([02 E3](02_shapes3d_streams.md)) | `permuted_100`: hidden 1 is a death/revival flow balance; every collapse ends with hidden 2 fully dead ([05](../../notebooks/results_summaries/05_unit_death.md)) |

## Where one project's tools answer the other's open questions

- **The acquisition assay is the other project's readout ladder, with controls.** Result 1's regimes (output remapping → fixed representation → encoder adaptation; [08](08_feature_acquisition_result1.md)) map onto the `notebooks` ladder (rename classes → soft remap → linear probe on frozen features → full retraining; [notebooks 01 E3](../../notebooks/results_summaries/01_pairwise_task_distance.md)). The ladder's prequential code length (bounded, split-free, self-gating) is a candidate replacement for fixed-budget frozen decoders, which here are often still improving at their last update.
- **Future-task geometry must be history-conditional.** `notebooks` shows that a distance between i.i.d. task pairs cannot predict plasticity loss by construction, and that only history-aware quantities track failure ([notebooks 03 E3](../../notebooks/results_summaries/03_cnn_streams.md)). The proposed "task geometry predicts when repairs work" paper (README) is compatible with this only if the geometry is measured relative to the checkpoint's own features, as planned.
- **Renewed vs persistent noise, on existing checkpoints.** Result 2's sharpest contrast ([09](09_history_acquisition_result2.md)) has ready-made long-stream counterparts in `notebooks`: `random_labels_20` (renewed every task) and the label-corrupted-once `*_lc*` streams (persistent), with checkpoints every 10 tasks ([notebooks 04 E7](../../notebooks/results_summaries/04_mlp_streams.md)).
- **Attributing deaths.** `notebooks` splits every unit death into "inputs changed" vs "optimizer moved the weights" from consecutive checkpoints, and finds dying units rotate rather than shrink ([notebooks 05 E1–E2](../../notebooks/results_summaries/05_unit_death.md)). The same analysis on the Shapes3D streams here (feature-switch vs permuted pixels) would test whether the shared push acts through rotation.
- **Shared push on MNIST.** Centring rescued the Shapes3D parity stream ([05](05_shared_push_validation.md)); centring the `notebooks` exp8 `permuted_classes` stream, whose deaths are purely optimizer-driven, would test whether the explanation transfers.

## Shared measurement pitfalls

- **Probe size and definition of "dead":** `notebooks` found a 2,000-row probe prefix fabricating impossible revivals; here, sign-based "dead" counts are not death for leaky ReLU, and health is measured on training images only.
- **Horizon:** both projects found apparently immune settings that collapse later.
- **Train accuracy:** here it is accumulated during the epoch; in `notebooks` the train-error index saturates while the network still fits — use held-out accuracy or final-model evaluations.
